# AI Landing Page Builder — Milestone

## Goal

Make **AI Build** the fastest path from an idea to a professional mobile-first landing page.

### User flow

`Create Landing Page → Tell Buy Now what you are launching → AI generates → Review → Edit sections → Upload/replace media → Preview → Save → Publish`

## Implemented in this PR

- [x] Mobile-first AI Build sheet opens automatically after a new landing page is created.
- [x] Natural-language prompt input with guided examples.
- [x] Optional starting direction for Fitness Coach, Coach, and Product Offer templates.
- [x] Authenticated `POST /api/ai/landing-page` endpoint.
- [x] Zod validation for AI requests and generated builder documents.
- [x] Provider abstraction through OpenAI-compatible `AI_BASE_URL`, `AI_API_KEY`, and `AI_MODEL` environment variables.
- [x] Structured JSON output is validated against the canonical conversion-builder schema before it reaches the editor.
- [x] Safe deterministic fallback when an AI provider is not configured or fails.
- [x] AI-generated documents use the same `builderDocument` consumed by the existing editor and preview.
- [x] Starter hero imagery is seeded for supported templates so AI-generated pages do not begin with empty image areas.
- [x] Existing mobile editor can immediately customize the generated page.
- [x] Existing image workflow remains available for device upload, starter media, and image URLs.
- [x] Existing live preview uses the generated document before save.

## Production gate

The AI provider must be configured in the deployment environment before the product claims live third-party AI generation. The fallback is intentionally safe and deterministic; it must not be presented to users as generated by an external model.
