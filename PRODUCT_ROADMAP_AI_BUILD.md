# AI Landing Page Builder — Milestone

## Goal

Make **AI Build** the fastest path from an idea to a professional mobile-first landing page.

### Primary user flow

`Create Landing Page → Choose goal → Describe audience + offer → Add photos/content → Add VSL/form links → AI generates → Review what was built → Edit sections → Replace media → Preview → Save → Publish`

Templates remain available as an optional manual starting point, but users no longer need to choose a template before they can build.

## Implemented

### AI Build v1

- [x] Mobile-first AI Build sheet opens automatically after a new landing page is created.
- [x] Natural-language AI generation endpoint with guided starting directions.
- [x] Optional starting direction for Fitness Coach, Coach, and Product Offer templates.
- [x] Authenticated `POST /api/ai/landing-page` endpoint.
- [x] Zod validation for AI requests and generated builder documents.
- [x] Provider abstraction through OpenAI-compatible `AI_BASE_URL`, `AI_API_KEY`, and `AI_MODEL` environment variables.
- [x] Structured JSON output is validated against the canonical conversion-builder schema before it reaches the editor.
- [x] Safe deterministic fallback when an AI provider is not configured or fails.
- [x] AI-generated documents use the same `builderDocument` consumed by the existing editor and preview.
- [x] Starter hero imagery is seeded for supported templates.

### AI Build v2 — creation experience

- [x] Three-step mobile creation flow: goal → business details → real content/assets.
- [x] Goal presets for Fitness Coach, lead generation, selling, and booking calls.
- [x] Structured audience, offer, outcome, price, and CTA inputs.
- [x] Upload up to six real images from the device before generation.
- [x] Uploaded images are stored through the authenticated Media API and immediately used in the generated builder document.
- [x] Fitness Coach uploads are mapped into the hero and transformation/social-proof area.
- [x] Optional VSL URL input.
- [x] Optional application/lead-form URL input and automatic primary CTA connection.
- [x] VSL section is added to the builder document when a VSL URL is provided.
- [x] Post-generation "Your page is ready" summary shows the generated sections and asset usage.
- [x] Generated content continues directly into the existing mobile editor and live preview.
- [x] Existing editor supports replacing images from device, template media, or URL.

### AI-first entry flow

- [x] Landing Page creation opens AI Build as the primary experience instead of forcing template selection first.
- [x] Templates remain accessible through an explicit "Browse templates instead" path.
- [x] AI-generated pages are created as draft pages using the canonical builder document.
- [x] New AI-created drafts hand off to the existing shared editor/preview flow.
- [x] AI creation can be launched again whenever the user returns to the Landing Pages creation screen.

## Production gate

The AI provider must be configured in the deployment environment before the product claims live third-party AI generation. The fallback is intentionally safe and deterministic; it must not be presented to users as generated by an external model.

Uploaded media currently uses the authenticated workspace media endpoint. Public/CDN delivery for uploaded assets remains a production backend milestone before treating uploaded assets as fully production-ready on published anonymous pages.
